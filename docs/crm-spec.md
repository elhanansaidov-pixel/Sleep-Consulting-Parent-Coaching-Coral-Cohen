# אפיון CRM: קורל כהן | ייעוץ שינה והדרכת הורים

## Context
- לאתר צריך מערכת ניהול פניות ולקוחות (CRM) פנימית, מאובטחת וברמה מסחרית.
- כרגע שאלון ההתאמה באתר לא שולח פניות לשום מקום.
- המשתמש שלח מסמך דרישות מלא (שלבים A–G) וענה על 10 שאלות אפיון.
- בשלב הזה **לא כותבים קוד**. זה האפיון לאישור.

## 1. אפיון מוצר: מה קורל עושה במערכת
1. **מקבלת פנייה**: הורה ממלא שאלון באתר. הפנייה נכנסת למערכת, וקורל מקבלת מייל. במייל יש רק שם, טלפון וקישור. התשובות הרגישות לא נכללות.
2. **מטפלת בפנייה**: כרטיס פנייה עם כל התשובות לשאלון, כפתור וואטסאפ או חיוג, שינוי סטטוס, עדיפות, תאריך מעקב הבא והערות.
3. **סוגרת עסקה**: הפנייה הופכת ל"משפחה" (לקוח) ול"עסקה" עם סכום וסטטוס תשלום.
4. **מנהלת את התהליך**:
   - **ייעוץ שינה**: שבוע נוכחי מתוך 8, שלב נוכחי מתוך 4, תאריך השיחה השבועית הבאה, וסיכום לכל שיחה.
   - **הדרכת הורים**: רשימת מפגשים וסיכומים.
5. **משימות ותזכורות**: משימה לכל ישות. בבוקר מגיע מייל יומי עם משימות להיום ומשימות באיחור.
6. **לוח בקרה**: פניות חדשות, פניות בטיפול, עסקאות פתוחות, הכנסות בפועל מול תחזית, תהליכים פעילים, משימות באיחור, שיעור המרה וזמן תגובה ממוצע.

## 2. ארכיטקטורה מוצעת
**עקרון**: לא מוסיפים Stack חדש. האתר בנוי על Astro, וה-CRM ייבנה כאפליקציה בנתיב `/admin` באותו פרויקט ועל אותו אחסון חינמי.

```
דפדפן (אתר)  ──POST──▶  Edge Function: submit-lead  ──▶  Postgres (leads)
                          ולידציה (zod), honeypot, Turnstile,              │ trigger
                          rate-limit, dedupe לפי טלפון                      ▼
                                                                 Edge Function: notify ──▶ Resend ──▶ מייל לקורל
דפדפן (/admin, React)  ──supabase-js + JWT──▶  Postgres + RLS (כל ההרשאות נאכפות ב-DB)
pg_cron (Supabase):  מייל יומי · סימון משימות באיחור · מחיקה אחרי 12 חודשים
GitHub Action שבועי:  פינג שמונע השהיית פרויקט חינמי
```

| שכבה | בחירה | נימוק |
|---|---|---|
| ממשק CRM | React 19 + TypeScript כ-island ב-Astro (`/admin/*`, client-side) | אותו מאגר ואותו פריסה. React מתאים לממשק אינטראקטיבי |
| רכיבים | Radix UI primitives (נגישים, תומכים RTL), עם עיצוב שלנו בטוקנים הקיימים | מראה פרימיום ייחודי, בלי עיצוב גנרי. shadcn בנוי על Radix, אבל דורש Tailwind |
| טבלאות | TanStack Table (headless) עם pagination בצד השרת | מוכח וקל |
| Kanban | dnd-kit | נגיש, כולל גרירה במקלדת |
| גרפים | SVG בהתאמה אישית (2–3 גרפים) | בלי ספרייה כבדה |
| DB | Supabase Postgres, EU (פרנקפורט) | RLS, Auth, Cron, Storage וקבצים, הכול בתוכנית החינמית |
| Auth | Supabase Auth: מייל וסיסמה, **MFA (TOTP) חובה** לשני המשתמשים, הרשמה עצמית כבויה | ספרייה מוכחת. בלי Auth שנכתב מאפס |
| מייל | Resend (חינמי, 3,000 מיילים בחודש) | המפתח נשמר כ-Secret ב-Supabase. אני לא רואה אותו |

**מה המשתמש עושה בעצמו (חד-פעמי):**
1. יוצר ארגון חדש ב-Supabase. ב-MCP אין כלי ליצירת ארגון.
2. מחבר את הסשן לארגון החדש, או מאשר לי ליצור בו את הפרויקט.
3. פותח חשבון Resend עם המייל של קורל ומדביק את המפתח ב-Supabase. אדריך אותך.

## 3. מבנה בסיס הנתונים (ראשוני)
| טבלה | שדות עיקריים |
|---|---|
| `profiles` | id (= auth.uid), full_name, role (`owner`/`tech_admin`), mfa_required |
| `pipeline_stages` | id, name, position, kind (`open`/`won`/`lost`). ניתן לעריכה |
| `leads` | id, created_at, source, service (`sleep`/`parenting`), stage_id, priority, next_follow_up_at, parent_name, phone, phone_normalized, email, child_age, answers (jsonb: ש' 5–12), consent_at, signed_name, duplicate_of, client_id, lost_reason |
| `clients` (משפחות) | id, parent_names, phone, email, tags[], notes, created_from_lead_id |
| `deals` | id, client_id, lead_id, service, amount, stage_id, expected_close, payment_status (`unpaid`/`partial`/`paid`), paid_amount, closed_at, lost_reason |
| `programs` | id, client_id, deal_id, service, start_date, current_week (1–8), current_stage (1–4), next_session_at, status (`active`/`paused`/`completed`) |
| `sessions` | id, program_id, held_at, kind (`intro`/`weekly`/`parenting`), summary |
| `tasks` | id, title, due_at, priority, status, lead_id / client_id / deal_id, completed_at |
| `activities` | ציר הזמן: entity, entity_id, kind (note/call/stage_change/payment…), body, actor, created_at |
| `notifications` | user_id, kind, ref, read_at |
| `audit_log` | actor, action, table, row_id, at, changed_fields. מתעד גם צפייה בפנייה. **בלי ערכי PII** |
| `submit_rate` | ip_hash, window_start, count. רלוונטי להגבלת הקצב |

**RLS:**
- `anon` לא קורא ולא כותב אף טבלה. הכתיבה נעשית רק דרך Edge Function.
- `owner`: הכול.
- `tech_admin`: קריאה מלאה, עריכת הגדרות. **אין לו מחיקה ואין ייצוא**.
- כל ההרשאות נאכפות גם ב-SQL.
- אינדקסים: לפי stage, created_at, next_follow_up_at, due_at ו-phone_normalized.

## 4. אבטחה ופרטיות
- MFA חובה.
- סשן קצר.
- הגנה מ-brute force: מגבלות ה-Auth של Supabase ו-captcha בכניסה.
- CSP קיים ומוחמר ל-`/admin`.
- XSS: כל טקסט מהגולשים מוצג כטקסט בלבד, בלי `innerHTML`.
- ולידציה בצד השרת.
- בלי PII בלוגים ובמיילים.
- Secrets נשמרים רק ב-Supabase.
- נעבור על Supabase advisors עד אפס אזהרות אבטחה.

**מחייב בדיקה משפטית ⚖️:**
- חוק הגנת הפרטיות (כולל תיקון 13) ותקנות אבטחת מידע: יש כאן **מידע רפואי על קטינים**, ולכן כנראה רמת אבטחה בינונית וחובות תיעוד.
- גישת המנהל הטכני חייבת להופיע במדיניות הפרטיות.
- תקופת שמירה של 12 חודשים.
- **גיבויים**: בתוכנית החינמית אין גיבוי שחזור נקודתי (PITR).
  - חלופה חינמית: ייצוא CSV שבועי ידני, שקורל מורידה בעצמה.
  - גיבוי מלא דורש Supabase Pro, ‎25$ לחודש.

## 7. סיכונים
- **R1** – פרויקט חינמי מושהה אחרי 7 ימים בלי פעילות. מענה: פינג שבועי.
- **R2** – אין גיבוי אוטומטי בתוכנית החינמית. מענה: ייצוא ידני או מעבר ל-Pro.
- **R3** – בתוכנית החינמית של Supabase מותרים 2 פרויקטים פעילים לכל משתמש. בחשבון כבר יש פרויקט, ולכן זה יהיה השני.
- **R4** – אין סביבת staging נפרדת. מענה: בדיקות RLS בתוך טרנזקציה שמבוטלת בסיומה (ROLLBACK), ונתונים סינתטיים בלבד.
- **R5** – התראות דפדפן באייפון עובדות רק אחרי התקנה למסך הבית.
- **R6** – לקוחות שמגיעים בוואטסאפ, וגם הדרכת הורים, לא ייכנסו ל-CRM בלי הזנה ידנית. **המלצה**: לאפשר לפחות "הוספת משפחה" ידנית.

## אימות (לכל שלב)
- בדיקות RLS: `anon`, `tech_admin` ו-`owner`, כל אחד מול כל טבלה, דרך `execute_sql` בתוך טרנזקציה שמבוטלת בסיומה.
- בדיקות יחידה (Vitest) ובדיקות E2E (Playwright): שאלון ← פנייה ← עסקה ← תהליך ← משימה.
- axe ללא שגיאות.
- צילומי מסך במחשב ובטלפון.
- Supabase advisors נקיים.
